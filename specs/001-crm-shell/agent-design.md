# metagross design consult — B-01 (read-only)

1. **Monorepo layout.** A single Turborepo with `apps/web` (React + Vite + MapLibre, deployed to Amplify Hosting) and `apps/api` (tRPC router on one Lambda behind API Gateway, plus `cdk/` for infra — the Cognito user pool, API Gateway, Lambda, and domain stacks). Shared code lives only in `packages/`: `packages/shared` for Zod schemas (session/lockout types, roadmap-section enum) and `packages/api-client` as the one tRPC client both the web app and any future app import — never duplicated. `infra/` holds the CDK app composed of the six stacks named in the constitution: `CrmData` (none yet for B-01, reserved for DynamoDB in B-07+), `CrmSync` (not touched here), `CrmApi` (API Gateway + Lambda + Powertools wiring), `CrmWeb` (Amplify app/branch config), `CrmDomain` (Route53/ACM/custom domain, `crm.{domain}`), `CrmOps` (Cognito user pool + the one seeded admin user + shared alarms/tags). B-01 only needs `CrmApi`, `CrmWeb`, `CrmDomain`, `CrmOps`; the other two stacks are declared empty/stubbed so later stories add to them rather than re-architecting.

2. **Cognito stack shape.** `CrmOps` defines one `UserPool` with self sign-up disabled (`selfSignUpEnabled: false`, no sign-up UI route), password policy from the constitution's security baseline, and account lockout via Cognito's native advanced security / custom auth challenge Lambda enforcing the 4th-attempt, 5-minute cooldown (a pre-auth Lambda trigger tracks failed attempts in a small DynamoDB counter keyed by username, since Cognito's built-in lockout isn't precisely "4 attempts/5 minutes"). One `UserPoolClient` (web, no client secret, SRP auth flow). A single seeded admin test user is created via a CDK custom resource (`AwsCustomResource` calling `AdminCreateUser` + `AdminSetUserPassword`) at deploy time, with the password placed only in Secrets Manager, never in code/logs/PR body. API Gateway uses a Cognito JWT authorizer (HTTP API's native JWT authorizer type, pointed at the pool's issuer and app client ID) on every tRPC route except `health.ping`, which stays public for the 3-second trace check.

3. **Map centering/bounding guarantee.** MapLibre GL is initialized client-side with `center: [-97.7431, 30.2672]` and a fixed `zoom` chosen to show the whole county on first paint — no server round trip, so there's no reload involved. The Travis County bounding-box guarantee ("always renders at least the box, no reload, no artificial pan/zoom limit") is implemented with `maxBounds` left unset (free pan/zoom) but a `fitBounds`-derived minimum: on `load` and on every `moveend`, a small client-side check compares the current viewport bounds against the county box and, if zooming out would have clipped below it, the `minZoom` is computed once from `map.cameraForBounds(countyBoxLngLatBounds)` so zooming out never drops under full-county visibility — this is a client-only calculation (no reload), recalculated only on resize.

4. **Disabled-section rows.** Each of Campaigns/Estimates/Jobs/Invoices/Outreach is a shared `NavRow` Atlas component rendered with `aria-disabled="true"`, `tabIndex={0}` (focusable so the tooltip is keyboard-reachable), and a `title`/Radix-style tooltip reading "Coming soon" on hover or focus. The row's click handler, instead of being removed, routes to a shared `/coming-soon/:section` route (reusing Task A A-13's Coming-soon component/pattern) that renders a "Back to Map" action — this satisfies "tapping one... opens a Coming Soon page" rather than doing nothing, while `aria-disabled` plus a non-interactive visual style signals it isn't a working feature. At 390px the same five rows render inside the collapsed "More" sheet via the same component, not a duplicate implementation.

5. **Top 3 risks.** (a) Cognito's native lockout semantics don't map 1:1 to "4th consecutive attempt, 5-minute cooldown" — needs a custom auth-challenge Lambda, which is new surface to get right and test. (b) The MapLibre min-zoom-from-bounds calculation is easy to get subtly wrong (e.g., aspect-ratio edge cases at 390px vs 1440px could still clip the county box) — needs viewport-specific verification, not just desktop. (c) `health.ping` tracing in X-Ray within 3s depends on API Gateway + Lambda cold start; cold Lambdas under default settings can blow past 3s on first hit, so provisioned concurrency or a pre-warm needs to be decided explicitly rather than assumed.

6. **Verify it's live.** Open `https://crm.{domain}` (never localhost — Playwright config must fail if pointed at localhost per Article I/X) in a private window, sign in with the shared seeded admin credentials pulled from Secrets Manager, confirm the Map screen renders centered on Travis County, and pull the matching `health.ping` trace from X-Ray (trace ID captured in evidence) within 3s of load. Separately exercise the nav rail/More sheet at 390/768/1440 to confirm `aria-disabled` rows and the Coming Soon route, screenshot each, and record the hosted URL, trace ID and screenshots in `docs/evidence/B-01.md`.
