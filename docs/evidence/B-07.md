## Defects found by running on the live stack (all fixed, each with a unit test)

1. The API sent no error code to the browser, so a duplicate showed a generic error (AC-2). The web unit test had mocked a shape the API never sends.
2. B-02's current-run pointer used a key that does not match `crm-leads` (pk plus sk), in three places.
3. The first-ever promote read a field that did not exist yet.
4. Concurrent creates surfaced DynamoDB `TransactionConflict` as HTTP 500 for 5 of 19 losers; they are now retried and get "Already a lead".
5. The lead list was oldest first, which broke "appears at the top of the list" (AC-1).
6. Notes were shown with their storage wrapper and JSON escapes.
7. The lead page's Status select used the browser default border, not an Atlas token.
8. The snapshot did not hold the permit (AC-1).
9. AC-5 flagged every lead whenever the manifest changed, even if the property was still in the new run.

## Honest notes

- **Intermittent failures during the proving round.** Several runs had failures in the note tests. The cause was in the test, not the app: the assertion looked at the whole Notes region, which also contains the textarea, so it passed on the text just typed, before the save finished, and the page then reloaded mid-save. Fixed in `294bf63` and `7607e3c` (checks the saved list only; the second commit restores a helper the first change removed by mistake). The earlier theory that Lambda throttling caused it was wrong and is withdrawn.
- **DNS under burst.** Once, TC-007's 20 simultaneous requests failed a DNS lookup on my machine (`ENOTFOUND`). The request never reached the server. The test now retries a failed lookup and reports how many it retried (`dnsRetried`), so it is counted and not hidden.
- **TC-NF-01 measurement.** Earlier samples (700, 1200, 2200 ms) were inflated by the test itself: Playwright's `toContainText` rechecks on a back-off schedule, so a lead that arrived just after a check was noticed one step later. A p95 of 2214 ms in one full run came from that, not from the product. The test now polls on every animation frame, and a direct API measurement (the lead is in the list on the first poll, 413 to 534 ms) agrees. The earlier figures are superseded.
- **One unexplained failure.** Full run 2 failed TC-NF-01 on desktop after 2.7 s. It passes alone 6 of 6 and in the latest desktop run. The temporary AWS credentials last 15 minutes, so expiry does not explain it. The test now reports the failing iteration (`60ad4d2`) so a repeat explains itself.
- **Lambda concurrency is 10** on this Free-plan account. The TC-007 test retries throttled calls the way a real client does; it is not a cause of any failure above.
- **Not every fix was seen failing first.** The API tests for the snapshot and AC-5 work were written with the code; the web tests were seen failing first.
- The test-case document (`testplans/B-07-test-cases.md`) predates the route correction (the Map is `/`, not `/map`), the per-permit button, TC-015b and the saved-notes assertion. It needs a version bump.
