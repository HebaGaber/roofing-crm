> Generated by `developmentsupport-featurelist` from `docs/01-intent.md`, then edited by you. Each row becomes one story file (`stories/{ID}-{slug}.md`) and one Spec Kit story branch. ## 1. Vision alignment

**Source vision:** `VIS-B` (approved 2026-10-21) · **Problem:** roofing sales teams can't search the public roof-age and open-permit signals by location or track the leads they find. · **Actors:** sales rep (primary), sales manager (optional), evaluator with the shared test login. · **Expected outcome:** a rep finds aged roofs and long-open roofing permits around a point in Travis County, inspects them, turns the best into tracked leads, and asks an agent in plain language.

### 4.6 Reuse from Task A

Some features copy code that Task A builds, then adapt it (PO decision, 2026-10-21). The copy lives **inside the existing B story**, with no separate port story. Each such story gets, in P8:

- a `reuses:` field in its front matter naming the Task A story and the copied paths;
- an acceptance criterion: *the Task A test cases for the copied part run in this repo, against this app's hosted URL, and pass; any test changed for the CRM is listed with the reason.*

Only code is copied, never linked: each repo is deployed and scored alone. Data still comes only from Task A's published CIDs or MCP (constitution B1). Copy with `../assessment-guide/scripts/copy-from-oracle.sh {path}`, which records the source commit in `docs/reuse-log.md`; the owning agent still reviews the copy.
